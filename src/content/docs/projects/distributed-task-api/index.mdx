**Problem:** High concurrency spikes were exhausting database connection pools and driving tail latency past 4.8 seconds during bursty background task submissions.  
**Solution:** Re-architected as an asynchronous, non-blocking pipeline: Envoy Ingress with distributed token-bucket rate limiting, Redis cache-aside reads, PostgreSQL transactional outbox writes, and decoupled worker queues.  
**Outcomes:** Sustained 15,000 requests/sec with p95 response time under 110ms and zero connection starvation.

## Tech Stack & Decision Matrix (Single Source of Truth)

All project pages reference this canonical stack:

| Component Layer | Technology | Version | Decision Reasoning & Trade-off |
| :--- | :--- | :--- | :--- |
| **API Runtime** | `Go / Gin` | `1.22` | Low latency, predictable memory footprint under concurrency |
| **Primary Storage** | `PostgreSQL` | `16.2` | ACID compliance, JSONB flexibility, transactional durability |
| **Caching Layer** | `Redis` | `7.2` | Sub-millisecond read latency, distributed token bucket rate limiting |
| **Orchestration** | `Kubernetes` | `1.30` | Horizontal Pod Autoscaling (HPA), automated rollouts and self-healing |
